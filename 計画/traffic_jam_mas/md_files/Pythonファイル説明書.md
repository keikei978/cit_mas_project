# 1. `traffic_jam_mas.py` — シミュレーション本体

## このファイルの役割

このプロジェクトの心臓部です。リング状の道路に車を並べて、車の動きを物理的に計算します。**他の5つのファイルはすべてこのファイルを `import` して使います**。

このファイル単体では絵を一切描きません。numpyだけで動く軽い計算専用です。これは意図的な設計で、実験で何百回もシミュレーションを回すとき、毎回 matplotlib の描画を通すと処理時間の大半が描画になってしまうから、計算と描画を分離してあります。

## 中身の構造

このファイルには4つの関数と2つのデータクラスが入っています。

### `IDMParams` データクラス

車1台の挙動を決める7つのパラメータをまとめたもの。デフォルト値はTreiber et al. 2000という論文の標準値です。

- `v0 = 16.0` — 希望速度(m/s)。約58 km/h。
- `T = 1.2` — 安全車間時間(秒)。前の車との時間的距離の目安。
- `a_max = 0.8` — 最大加速度(m/s²)。
- `b_comf = 1.5` — 快適減速度(m/s²)。普通のブレーキの強さ。
- `delta = 4` — 加速度指数。希望速度に近づくときの加速の落ち方を決める。
- `s0 = 2.0` — 最小車間距離(m)。停止時の車と車の隙間。
- `l_veh = 5.0` — 車の長さ(m)。

実験で変えたいパラメータだけ書き換えれば、残りはデフォルト値が使われます。例:`IDMParams(T=1.8)` なら、`T` だけ1.8秒で他は標準値。

### `SimParams` データクラス

シミュレーション全体の設定。

- `ring_length = 350.0` — 環状道路の周長(m)。
- `n_cars = 28` — 車の台数。
- `dt = 0.25` — 時間刻み(秒)。1ステップで0.25秒進む。
- `n_steps = 600` — 総ステップ数。デフォルトだと150秒分のシミュレーション。
- `perturbation = 'stop_one'` — 最初に加える乱れの種類。
  - `'stop_one'`:1台だけ速度ゼロにする(強い摂動)
  - `'small'`:1台だけ速度を5%落とす(弱い摂動)
  - `'none'`:何もしない(浮動小数点誤差のみ)

### `initialize_state(idm, sim)` 関数

シミュレーション開始時の状態を作ります。

- 車を環状道路上に**等間隔**に並べる。例えば350mに28台なら12.5m間隔。
- 全車の速度を希望速度の60%(=9.6 m/s)で揃える。
- 最後に `sim.perturbation` の指定に応じて、1台目だけ乱す。

戻り値は位置の配列 `x` と速度の配列 `v`。どちらも長さがN(車の台数)のnumpy配列です。

### `step(x, v, idm, sim)` 関数

1ステップ(0.25秒)だけ時間を進めて、新しい位置と速度を返します。**このファイルで一番大事な関数**。中身を順に追うと:

1. `np.argsort(x)` で車を位置順に並べ替える。誰が誰の前にいるかを特定するため。
2. `np.roll` で「各車の前を走っている車」の位置と速度を取得。リング状なので最後尾の車の前は先頭の車。
3. 前の車との車間距離(`gap`)を計算。`mod` を使って一周分の処理をする。
4. IDMの公式に従って、各車の加速度を**全車一括で**計算。ここがnumpyを使う旨み。Pythonのforループで1台ずつ計算すると遅いけれど、numpyの配列演算なら一発で全車分が出る。
5. 加速度から新しい速度を計算。バックは禁止なので `np.maximum(v, 0)` で負の速度を0に丸める。
6. 速度から新しい位置を計算。これも `mod ring_length` で一周分を処理。
7. ソートした順序を元に戻して返す。

### `run_simulation(idm, sim, record_positions=False)` 関数

シミュレーションを最初から最後まで走らせるメイン関数。

- `idm` と `sim` を渡さなければデフォルト設定が使われます。
- 中で `initialize_state` を呼んで初期状態を作り、あとは `step` を `sim.n_steps` 回繰り返すだけ。
- 各ステップで「全車の平均速度」と「全車の最低速度」を記録します。
- `record_positions=True` を指定すると、全車の全ステップの位置と速度も記録します(時空間プロット用)。**ただしメモリを食う**ので、必要なときだけ True にする。

戻り値は辞書で:
- `'avg_v'`:各ステップの平均速度(長さ `n_steps` の配列)
- `'min_v'`:各ステップの最低速度
- `record_positions=True` のとき追加で:
  - `'x_history'`:形状 `(n_steps, n_cars)` の位置履歴
  - `'v_history'`:同じ形の速度履歴

### `summary_stats(result, transient=200)` 関数

`run_simulation` の結果を受け取って、**過渡状態を除いた定常部分**の要約統計を返します。最初の `transient` ステップ(デフォルト200)は捨ててから集計。

戻り値の辞書:
- `mean_avg_v`:平均速度の時間平均(流れの良さの指標)
- `mean_min_v`:最低速度の時間平均(渋滞の深刻さ)
- `std_avg_v`:平均速度のばらつき(波が立っているかの指標)
- `wave_amplitude`:平均と最低の差(波の振幅)

## このファイル単体を実行すると

```
python traffic_jam_mas.py
```

デフォルト設定でシミュレーションを1回走らせて、計算時間と `summary_stats` の結果が表示されます。「ちゃんとimportできて動くか」の動作確認用です。

# 2. `visualize_animation.py` — アニメーション可視化

## このファイルの役割

シミュレーションの結果を**動画として見せる**ためのファイル。発表のつかみ用GIFを作ったり、現象が正しく再現されているかを目で確認したりするときに使います。

## 中身の構造

### `to_xy(s, ring_length)` 関数

リング道路上の位置(弧長 `s`)を、画面上のxy座標(円の上の点)に変換するヘルパー。リングを単位円として、`(cos θ, sin θ)` を返すだけ。

### `make_animation(idm, sim, save_gif=True)` 関数

このファイルの本体。流れはこう:

1. `traffic_jam_mas.run_simulation(record_positions=True)` でシミュレーションを走らせ、全ステップの位置と速度を取得。
2. matplotlibで左右2つの図を用意:
   - 左:リング道路を上から見た図(単位円の上に車を散布図でプロット)
   - 右:時間に対する平均速度と最低速度のグラフ
3. `FuncAnimation` で1ステップずつフレームを進めるアニメーションを作成。各フレームで:
   - 車の位置を `set_offsets` で更新
   - 車の色を `set_array` で更新(緑=速い、赤=遅い、カラーマップは `RdYlGn`)
   - 右の速度グラフに新しい点を追加
4. 画面に表示。
5. `save_gif=True` なら、実行日時を入れたファイル名(例:`traffic_20260520_143022.gif`)でGIF保存。

## このファイル単体を実行すると

```
python visualize_animation.py
```

デフォルトパラメータでアニメーションが画面に出て、最後にGIFが保存されます。

GIF保存に30秒〜数分かかります。実験で何度もシミュレーションを回すときはこのファイルを使わず、土台を直接呼ぶほうが速いです。

# 3. `experiments.py` — 実験2・3(基礎実験)

## このファイルの役割

基礎の2つの実験を1つのスクリプトにまとめたもの。

- **実験2**:車の台数Nを10台から40台まで1台刻みで変えて、定常状態の平均速度と最低速度を測る。「何台から渋滞が始まるか」を見る。
- **実験3**:台数を28台に固定して、安全車間時間Tを0.6秒から2.0秒まで0.1秒刻みで変える。「運転の慎重さで渋滞は変わるか」を見る。

## 中身の構造

### `run_sweep(varying_param, values, fixed_params=None)` 関数

1つの変数を動かしてスイープする汎用関数。

- 引数 `varying_param`:動かしたいパラメータ名(文字列)。例:`'n_cars'` または `'T'`。
- 引数 `values`:そのパラメータが取る値のリスト。
- 引数 `fixed_params`:固定するパラメータの辞書。

中では `values` の各値について:
1. パラメータ名がIDM側なのかSim側なのかを判定して、適切に振り分ける。
2. `run_simulation` を呼んで結果を取得。
3. `summary_stats(transient=300)` で定常部分の統計を取る。過渡を300ステップ捨てるのは、N が臨界付近だと波が立ち上がるのに時間がかかるため。
4. 平均速度と最低速度をリストに追加。

戻り値は (平均速度のリスト, 最低速度のリスト)。

### メインの実行部分

- 実験2(N スイープ):`n_cars` を 10〜40 で動かし、`exp2_data.npz` に保存。
- 実験3(T スイープ):`T` を 0.6〜2.0 で動かし、`exp3_data.npz` に保存。
- 結果を1枚の画像に左右並べてプロットし、`experiments_2_and_3.png` として保存。

## このスクリプトを実行すると

```
python experiments.py
```

進捗が標準出力に流れ(各ケースの結果)、最後に2つのnpzファイルと1枚のpngファイルが生成されます。

## 結果から読めること

- 実験2のグラフ:N が小さい(10〜18台)うちは平均速度も最低速度もデフォルトの初期速度(9.6 m/s)近く。ある台数(およそ20〜22台)を超えると、最低速度がガクッとゼロに張り付き始める。**ここが「臨界点」**。
- 実験3のグラフ:T が小さい(0.6〜1.0秒)と渋滞、T が1.5秒を超えるあたりから渋滞が消えて速度が回復。**車を1台も減らさずに渋滞が消える**。

# 4. `experiment4_growth.py` — 実験4(成長率測定)

## このファイルの役割

実験2・3では「速度のグラフを目で読んで、だいたいこのへんが境目」と判断していました。それを**数値で正確に確定する**ための装置です。

「渋滞波の成長率 γ」を導入します。これは、小さな乱れが時間とともに育つ勢いを表す数値で、γ > 0 なら渋滞へ、γ < 0 なら自由流へ、γ = 0 がちょうど境界。

3つの変数(道路長 L、台数 N、車間時間 T)それぞれで γ を測り、γ = 0 になる点(臨界値)を求めます。

## 重要な内部設定(冒頭の定数)

```python
FIT_START = 100
FIT_END = 500
N_STEPS = 800
PERTURBATION = 'small'
```

- `FIT_START`, `FIT_END`:成長率を測るためのフィット区間。事前検証で「log-振幅がきれいに直線になる区間」として確定した値。**ここを変えると γ の値が変わる**ので原則固定。
- `N_STEPS`:シミュレーションのステップ数。フィット区間に余裕を持たせるため800。
- `PERTURBATION`:摂動の強さ。`'small'` は1台を5%減速だけ。**強い摂動では成長率が測れない**(指数成長の初期勾配が見えなくなる)ので、ここは弱い摂動が必須。

## 中身の構造

### `measure_growth_rate(v_history, dt, fit_start, fit_end)` 関数

成長率 γ を測る核心の関数。手順は:

1. 各ステップの「全車速度の標準偏差」を計算。これを「波の振幅」とみなす。みんな同じ速度ならばらつきゼロ、誰かが遅い・誰かが速いとばらつきが出る、という素直な指標。
2. 振幅の対数を取る。指数成長 `A(t) ∝ exp(γt)` は対数を取ると直線 `log A = γt + 定数` になる。
3. フィット区間 `[fit_start, fit_end]` で、`log(振幅) vs 時間` を1次多項式(直線)でフィット。
4. その傾きが γ。

おまけで決定係数 R² も計算して返します。R² が1に近いほど「ちゃんと直線だった」ことの確認。

### `run_growth_sweep(varying_param, values, fixed_params)` 関数

`experiments.py` の `run_sweep` の成長率版。各ケースで:

1. `run_simulation(record_positions=True)` で速度履歴を取得。
2. `measure_growth_rate` で γ と R² を計算。
3. リストに追加。

R² が低い(< 0.9)ときは警告マークを表示します。

### `find_zero_crossing(values, gammas)` 関数

γ の符号が変わる点(γ = 0 の点)を**線形補間**で求める関数。隣り合う2点で γ の符号が変われば、間に交差点があるはずなので、直線で補間して交差点の x 座標を返します。1スイープに複数の交差があれば全部返します。

### メインの実行部分

3つのスイープを順に実行:

- **実験4-A**:`ring_length` を 250〜600m で 25m 刻み(15ケース)。N=28固定。
- **実験4-B**:`n_cars` を 10〜45台で 1台刻み(36ケース)。L=350m固定。
- **実験4-C**:`T` を 0.6〜2.2秒で 0.1秒刻み(17ケース)。N=28, L=350m固定。

それぞれ npz として保存し、最後にプロット2枚を作ります。

### プロット用ヘルパー `plot_panel`

各サブ実験のグラフを1パネルずつ描く関数。安定/不安定ゾーンを薄く色分けし、γ = 0 の水平線、ゼロ交差点の縦線とラベルを描画。

## このスクリプトを実行すると

```
python experiment4_growth.py
```

出力ファイル:
- `exp4A_data.npz`, `exp4B_data.npz`, `exp4C_data.npz` — 各スイープの生データ
- `exp4_growth_rate.png` — 3パネル図(γ vs L/N/T)
- `exp4_density_collapse.png` — 密度軸での重ね描き(L スイープとN スイープが重なる図)

最後に標準出力に臨界値のまとめが出ます:
```
L* = [515.91]  (m)
N* = [19.54]
T* = [1.71]  (s)
```

## 結果から読めること

3つの境目の数字が出ます。
- **L\* ≈ 516 m**:N=28固定で、これより道路が短いと渋滞。
- **N\* ≈ 19.5 台**:L=350m固定で、これより車が多いと渋滞。
- **T\* ≈ 1.71 秒**:N=28, L=350m固定で、これより運転がせっかちだと渋滞。

さらに `exp4_density_collapse.png` で、Lスイープ(N=28固定で密度を変えていることに相当)とNスイープ(L=350固定で密度を変えていることに相当)が、密度軸でぴったり重なります。**3変数の問題が2変数(密度・車間時間)に集約された**証拠です。

```python
        # 該当する (N, T) で run_simulation して gamma を測る
        gamma_grid[i, j] = ...
```

全493ケース(29×17)。1ケース約 0.2 秒なので、合計1〜2分。

### プロット

`pcolormesh` で2次元のヒートマップを描き、その上に `contour` で γ = 0 の等高線(黒線)を重ねます。境界線が「綱引きの均衡線」になる仕掛け。

## このスクリプトを実行すると

```
python experiment4_NT_map.py
```

横軸が混雑度、縦軸が運転の慎重さ。色が渋滞の勢い、黒い線が境界。

- **右下(混んでてせっかち)**に最濃の赤、最強の渋滞ゾーン。
- **左上(空いてて慎重)**が青、自由流ゾーン。
- **黒線が綱引きの均衡線**。混雑で右にずれた分を、運転を慎重にして上にずらせば、青い側に留まれる。
- 黒線の傾きは「車1台と車間時間の交換レート」を表す。場所によって傾きが変わるので、「空いている道路ほど運転改善の効きが大きい」と読める。

# 6. `experiment5_mixed.py` — 実験5(混在実験)

## このファイルの役割

ここまでの実験はすべて「全車が同じ車間時間」を前提にしていました。でも現実の道路では慎重な人もせっかちな人も混じっています。それを再現するための実験。

慎重なドライバー(車間時間2.0秒)とせっかちなドライバー(0.8秒)を1つのリングに混ぜ、慎重派の割合を 0%→100% でスイープして、各割合で成長率を測ります。「**何割の人が慎重なら渋滞が消えるか**」が答えになります。

## 実装上の特徴(重要)

土台の `traffic_jam_mas.py` の `step` 関数は、`idm.T` というスカラー値を全車に適用する作りになっています。**車ごとに違う T を扱えません**。

これを実現するために、`traffic_jam_mas.py` を改変するのではなく、**車別 T 対応の step 関数をこのスクリプト内に独自に持っています**。これで土台は無改変のまま、既存の実験2〜4が影響を受けない設計を保てます。

ただし注意点が1つあって、`step` の中で車を位置順にソートする処理(`np.argsort`)があるので、**T配列も同じ順序でソートしないと、別の車のTを使ってしまうバグ**になります。`step_heterogeneous` ではこれを忘れずに処理しています。

## 中身の構造

### `step_heterogeneous(x, v, T_array, idm, sim)` 関数

土台の `step` の車別T対応版。IDM の数式は土台と完全に同一で、唯一の違いは `s_star` の計算で `idm.T`(スカラー)ではなく `T_sorted`(配列、位置順にソート済み)を使う点。

### `run_mixed_simulation(T_array, idm, sim)` 関数

土台の `run_simulation` の車別T対応版。中で `step_heterogeneous` を `n_steps` 回呼ぶだけ。速度履歴を返します。

### `measure_growth_rate(v_history, dt)` 関数

実験4と同一のロジック。log-振幅の傾きを γ として返す。

### `make_T_array(n_cars, frac_cautious, T_cautious, T_aggressive, arrangement, rng)` 関数

「慎重派が `frac_cautious` の割合」の T配列を作る関数。

- `arrangement='random'`:慎重派とせっかち派をランダムに配置(これがデフォルト)
- `arrangement='blocked'`:慎重派を1か所に固める(配置の影響を見る検証用)

ランダム配置のときは `rng.choice` で慎重派にする車のインデックスを選びます。

### メインの実行部分

設定:
- N=28台(臨界付近に固定)
- 慎重派の車間時間 2.0秒、せっかちな車間時間 0.8秒
- 慎重派割合を 0% から 100% まで 5% 刻み(21段階)
- 各段階で**20回ずつ試行**して平均を取る(配置運の影響を平均化)

各試行で乱数シードを `trial` 番号に固定するので、結果は再現可能。

すべての試行が終わったら:
- 各割合での γ の平均と標準偏差を計算
- ゼロ交差(必要な慎重派の最低比率 f\*)を線形補間で算出
- npz と png に保存

### プロット

`fill_between` で標準偏差の帯を薄く描き、`plot` で平均線を上に重ねます。γ = 0 の水平線、ゼロ交差の縦線も。

## このスクリプトを実行すると

```
python experiment5_mixed.py
```

出力ファイル:
- `exp5_data.npz` — 生データ
- `exp5_mixed_drivers.png` — γ vs 慎重派割合のグラフ

## 結果から読めること

- 慎重派 **0%(全員せっかち)**:γ ≈ +0.023、強い渋滞。実験4でT=0.8のときの値と一致。
- 慎重派 **100%(全員慎重)**:γ ≈ −0.005、渋滞解消。実験4でT=2.0のときの値と一致。
- **境界は約72%**:つまり**4人に3人弱が慎重に運転すれば、残りがせっかちでも渋滞は消える**。
- 境界付近では帯が γ = 0 をまたぐ:「72%ぎりぎりだと配置運で揺れる、確実に消すには80%が安全」という現実的な含み。
- 20〜30%付近でカーブが一段平らになる:「せっかちな人の塊が残ると渋滞源として効き続ける」ため。

## 整合性チェックの意味

両端(0% と 100%)の γ が実験4のTスイープの値と一致することは、**車別T対応コードが正しく動いている裏付け**になります。独立して書いたスクリプトが、本体と独立に動くのに同じ結果を出す。これがないと「もしかして実装ミス?」が拭えない。整合性が取れているのは大きな安心材料です。

# 全体像

このプロジェクトは、こういう物語で進んできました。

1. **土台を作った** (`traffic_jam_mas.py`)
   IDMで車の動きを計算する基盤。numpy で全車一括計算する設計で、実験を高速に回せるようにした。

2. **目で見える形にした** (`visualize_animation.py`)
   渋滞波が逆向きに進む様子を動画化。シミュレーション計算と描画を分離する設計を維持。

3. **境目を探した(基礎)** (`experiments.py`)
   車の台数と運転の慎重さで境目があると分かった。ただし「だいたいこのへん」の精度。

4. **境目を数字で確定した** (`experiment4_growth.py`)
   成長率 γ という新指標で、3つの境目を正確な数字に。さらに密度collapseを発見。

5. **地図にした** (`experiment4_NT_map.py`)
   混雑と慎重さの綱引きを1枚の絵に。

6. **現実に近づけた** (`experiment5_mixed.py`)
   全員でなく4人に3人で足りると分かった。研究で最も力強い結論。

土台 → 可視化 → 基礎発見 → 精密化 → 一般化 → 現実化、という流れです。それぞれの段階のファイルが独立して動くように残してあるので、「あの実験だけもう一度回したい」というときも単独で実行できます。
